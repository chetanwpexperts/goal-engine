Under the hood

Machine learning where it helps, proof where it matters

A trained language model works out what you mean. Written rules and real database engines decide what is true, so every answer comes with evidence, not a guess.

  1. Understand Character and word n-grams, TF-IDF and logistic regression classify the request. Spelling slips and Hinglish are handled.
  2. Read The query is split into blocks: which rows each step keeps, what it groups, where a join multiplies rows.
  3. Prove Each suspicion is checked on real MariaDB and PostgreSQL engines, read-only, and the answer says how sure it is.
  4. Fix You see the change and the rows it touches first. Nothing runs without your approval, and every change can be undone.

It keeps learning, safely. When three different people confirm what a sentence meant, that sentence becomes a training example and the model retrains within minutes. One person alone can't teach it, so it can't be poisoned, and nobody's details are kept.

What an answer looks like

Someone asked

"This should show paid and shipped orders, but I only get the paid ones."

SELECT id, amount
FROM orders
WHERE status = 'paid' OR 'shipped';

DBaba Proven from the query

OR needs the column again. OR 'shipped' doesn't compare anything with status. MySQL turns the word into the number 0 and quietly keeps only the paid orders; PostgreSQL refuses the query.

WHERE status IN ('paid', 'shipped')

Checked on MariaDB and PostgreSQL: the fixed query returns both kinds of order.
